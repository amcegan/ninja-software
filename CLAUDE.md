# Ninja Software — ninjasoftware.ie

Static marketing site for an Irish AI consultancy. Plain HTML/CSS/jQuery,
hand-edited, **no build step**. Deployed by GitHub Pages from this repo.

## The single most important fact

**This repo *is* the deployed branch.** `CNAME` points at `ninjasoftware.ie`
and GitHub Pages serves the repo root. Anything committed is published —
there is no `dist/`, no build output, no staging. Adding a large file to the
repo means adding it to the page weight of a live site.

## Layout

```
*.html               8 indexable pages + 404.html
style.css            main stylesheet (hand-edited)
css/responsive.css   breakpoint overrides (hand-edited)
css/bootstrap.min.css, css/owl.carousel.css     vendor
css/vendor/          self-hosted third-party CSS (aos, Font Awesome subset)
webfonts/            subset Font Awesome woff2 files
js/                  jquery, bootstrap bundle, aos, owl, smartscroll, scripts.js
img/                 deployed derivatives; see img/README.md
img/_src/            full-res originals — GIT-IGNORED, never commit
```

`Staticfile` (contents: `/`) is a leftover from another host; GitHub Pages
ignores it.

## Local development

There is no dev server script. Serve the repo root over HTTP:

```sh
cd /Users/user/projects/ninja-software && python3 -m http.server 8777
# then http://127.0.0.1:8777/index.html
```

**Do not open pages with `file://`.** `404.html` uses root-absolute paths and
will appear completely unstyled from disk — see the 404 note below.

## Gotchas that are easy to break

These are the things that have already caused bugs. Read before editing.

### Font Awesome is a 17-icon subset

`css/vendor/fontawesome-subset.css` + `webfonts/*.woff2` were generated by
subsetting FA 6.1.1 down to only the icons in use (354KB → 4.1KB). **Using an
icon that isn't in the list below renders nothing** — the glyph is not in the
font. Current set:

```
arrow-up bars compass diagram-project envelope facebook-f file-lines
instagram laptop-code linkedin-in location-dot paper-plane phone robot
rocket truck x
```

To add one: find its codepoint in upstream FA CSS, add a `.fa-NAME:before`
rule to the subset CSS, and re-run `pyftsubset` over the upstream TTF with the
enlarged unicode list. Subset from the **TTF**, not the woff2 — the woff2
fails with a brotli decode error.

### Bump the CSS cache-buster when editing stylesheets

`style.css` and `css/responsive.css` are linked as `?v=N` on all 9 HTML files.
**Editing either without bumping `N` means returning visitors keep the old
CSS.** Currently `v=6`. This has already caused a false "the fix didn't work"
once.

### The same selector appears at several breakpoints

`.hero-area p` is written in `style.css` **and** in both the 768–991 and
≤767 blocks of `css/responsive.css`. The colour used to be repeated in all
three, so changing one left phones unfixed while desktop looked right; it is
now declared **once** in `style.css` and inherits, with the responsive rules
overriding only `font-size` (and `text-align` on mobile).

The selector still repeats, so the habit stands: **grep the selector across
both stylesheets before editing**, and if you add a property to the base rule,
check no breakpoint is already overriding it.

### The hero blue cannot be darkened

`img/h-bg.jpg` has `#6591C2` baked into all four corners to blend with
`.hero-area`'s background. Changing that background colour leaves a visible
rectangular seam where the image sits. Contrast problems on the hero must be
solved by darkening *text*, not the background.

### WebP is used only where it actually wins

`logo.png`, `ninjalast.png` and `sword.png` are PNG on purpose — pngquant beat
WebP for those (palette-quantised flat artwork compresses better than WebP).
Don't "finish the job" by converting them. `img/README.md` has the full table
and the regeneration commands.

### 404.html must use root-absolute paths

GitHub Pages serves `404.html` for *any* unmatched URL at *any* depth. A
visitor hitting `/a/b/c` resolves relative paths against `/a/b/`, so relative
asset paths 404. Every `href`/`src` in that file is root-absolute (`/style.css`)
and must stay that way. Consequence: it only renders correctly over HTTP, never
from `file://`.

### The header jump

`header` is static, and a scroll handler adds `.fixed-menu` which switches it
to `position: fixed` — removing 88px from the flow and shifting content up.
This is why `index.html` re-applies the anchor scroll on load (so
`index.html#Services` from another page lands correctly). It is also a CLS
contributor and the top item on the old `img/todo.txt`: *"Remove fixed-menu
JavaScript and css"*. Still outstanding.

### Page-scoped scripts

`owl.carousel.js` loads only on `index.html`; `smartscroll.js` only on
`index.html` (the one page with `data-scroll` attributes). `js/scripts.js`
guards its `.owlCarousel()` calls with `$.fn.owlCarousel && …length` — removing
those guards breaks every page that doesn't load owl.

### Calendly is lazy-loaded

CTAs call `openCalendly(url)`, defined inline in the `<head>` of the 6 pages
that have a Calendly CTA (not `404.html`, `case-study-graph-rag.html` or
`workflows.html`). It injects Calendly's CSS/JS on first click so they stay
off the critical path. Don't reintroduce the `<script src="…calendly…">` tags,
and if you add a CTA to a page, add the loader too.

## Conventions

- Cross-page in-page links use `index.html#Section`, not `#Section` — the
  `#home`/`#Services`/`#about`/`#contact` sections exist only on `index.html`.
  Exception: `software-eng.html` has its own `#contact`.
- Every `<img>` carries `width`/`height` (CLS), descriptive `alt`, and
  `loading="lazy"` below the fold. The hero image has `fetchpriority="high"`.
- Each page's `<title>` is ≤60 chars and ends with `| Ninja Software`;
  `og:title` and `twitter:title` mirror `<title>` exactly — change all three.
- Service pages carry `Service` JSON-LD with an identical key set, whose
  `provider.@id` points at the Organization node on `index.html`. The case
  study uses `TechArticle`. `404.html` has none (it is `noindex`).
- The `.related-services` block at the foot of service pages provides internal
  cross-linking; icons must come from the FA subset.

## After changing pages

`sitemap.xml` `lastmod` values are **currently stale** (`2026-09-20`, while
pages changed `2026-09-22`). Update them when publishing content changes.
`robots.txt` is correct and blocks nothing — never add `Disallow` rules for
`/css/` or `/js/`, which would stop Googlebot rendering the site.

## Verifying changes

There are no tests. Verify in a real browser — headless Chrome is installed:

```sh
CHROME="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
"$CHROME" --headless=new --disable-gpu --hide-scrollbars \
  --virtual-time-budget=12000 --window-size=1440,1000 \
  --screenshot=/tmp/shot.png http://127.0.0.1:8777/index.html
```

**Mobile screenshots: `--window-size=390,…` lies.** Headless lays out wider and
crops the PNG, which looks exactly like a horizontal-overflow bug. To get a
true 390px viewport, load the page in a 390px-wide `<iframe>` from a wrapper
page and screenshot that. This has produced two false bug reports already.

Lighthouse is installed (`lighthouse <url> --preset=desktop`). Run **both**
presets — the mobile preset catches contrast failures the desktop one misses.

Installed tooling: `cwebp`, `pngquant` (brew), `node` + `lighthouse`.
`fonttools`/`pyftsubset` were installed in a throwaway venv and will need
reinstalling (`pip install fonttools brotli`).
